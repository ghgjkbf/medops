# Agent 工具调用策略笔记（外部思想吸收）

来源：[jacob-balslev/skills](https://github.com/jacob-balslev/skills) `tool-call-strategy`（MIT）。该 skill 在 skills.sh 仅 9 安装 / 仓库 1 star，**未经社区验证，只吸收思想，未安装**。检索渠道：find-skills（skills.sh + `npx skills find`）。吸收日期：2026-09-07。适用性判断：原文面向 coding-agent harness（Claude Code/Cursor 类），直接可迁移约三成，本文只保留映射到 medops 智能层后成立的部分。

## 1. 三重成本模型（核心心智模型）

每次工具调用同时付出三种成本：

| 成本 | 机理 | 对 medops 的放大效应 |
| --- | --- | --- |
| token | schema 开销 + 结果体积 | 6 个 MCP Server 的工具 schema 常驻 prompt；结果 JSON 随轮次累积 |
| 延迟 | 网络往返 + 决策时间 | streamable-http 每设备一跳；串行 N 台设备 = 延迟求和 |
| 上下文污染 | 结果永久留在对话史 | **DeepSeek/Qwen 64K~128K 上下文远小于前沿模型**；降级链走到 Ollama 本地小模型时信噪比问题最致命 |

关键论断：上下文不是预算问题，是**信噪比**问题——5 次多余读取不是 5 倍 token，而是把有用信号推离注意力窗口，污染后续所有决策。

## 2. 证据纪律（纠偏：不是"调用越少越好"）

好的策略不是工具节制，而是证据纪律：**必要的一次验证调用很便宜，幻觉一个答案很贵**。对应 medops：写操作（创建工单、下发控制命令）成功返回后追加一次读回验证，属于合理支出，不属于浪费。反例才是无界日志转储、重复读取。

## 3. 映射到 medops 的六条守则

1. **结果先裁剪再进上下文**。MCP 工具返回值在进入对话史前做结构化裁剪/摘要（只保留决策相关字段）。log_pipeline 的 analyzer 已按设备分组归因、降级为规则摘要，同一思路应推广到 secretary/inspector 的所有 MCP 结果路径。
2. **扇出并行**。巡检查 N 台设备状态是 N 次独立调用 → LangGraph 并行分支一次发出，墙钟 = max(单次) 而非 sum。依赖调用（先读后写）保持串行。判定标准：后一次调用是否使用前一次的输出。
3. **冗余规避**。同一事实一次获取。BaseAgent 的 ToolCall 轨迹（`core/agents/base.py`）可用于自检：本轮是否已取过该设备/该状态，命中则直接复用轨迹。
4. **Poka-yoke 入参校验**。MCP 工具对非法入参快速失败，错误信息要能引导 LLM 下一轮自纠（指明期望格式），而不是裸抛异常让它盲猜。工具 docstring 即描述（见 `notes/mcp-sdk-v2-api.md` §1），描述质量直接决定 LLM 选择质量——写描述就是写路由。
5. **确定性批操作不走逐次 LLM 调用**。已知输入→已知输出的操作（批量状态快照、报表聚合）走内置实现/脚本一次完成；只有需要推理中间结果的才逐次工具调用。这为既有决策"system/report 是 core 内置工具不走 MCP"提供了理论依据，可写入设计文档论证段。
6. **上下文预算意识**。降级链每往下一层（DeepSeek→Qwen→Ollama），可用上下文越小，工具结果越要小。L4 规则兜底不依赖上下文，是这条的天然终点保障。
